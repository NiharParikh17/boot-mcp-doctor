# Migrating to 0.1.2 from 0.1.1

**Migration needed: no.** Change the version to 0.1.2. There are new log lines, failures are reported differently, and Spring Boot 4.0 is now supported.

## Steps

None.

## What behaves differently

- **A new log line at startup** says whether boot-mcp-doctor supports the application's Spring Boot and Spring AI versions, at INFO, or WARN when it doesn't support them. It is logged even when `boot-mcp-doctor.enabled` is not `true`, so applications that have the dependency but leave it off now log one line. To hide it unless the versions are unsupported, set `logging.level.com.nhparikh.repo.bootmcpdoctor.autoconfigure.CompatibilityLog: WARN`. See [Compatibility](../guide.md#compatibility) in the guide.
- **Every tool call is logged** once it finishes, with its arguments, masked, the caller, the client and the outcome: INFO when it succeeds, WARN when it is refused or fails. Applications that use the tools log one line per call. To log only refused and failed calls, set `logging.level.com.nhparikh.repo.bootmcpdoctor.autoconfigure.ToolCallLog: WARN`. See [When a tool is called](../guide.md#when-a-tool-is-called) in the guide.
- **An unexpected failure is reported without its message.** A tool that fails now returns an error saying `<tool> failed with <exception>. The application's log has the details.`, and the stack trace is logged with the call. Before, the client got the exception's own message, which could contain configuration values, and nothing was logged. `get_health` used to answer `Health check failed: <message>` in this case.

0.1.2 also adds the [compatibility chart](../compatibility.md) and these migration guides.

## Removed or renamed

None.

## Requirements

Spring Boot 4.0 is now supported, as well as 4.1. On Spring Boot 4.0.4 and 4.0.5, use Streamable HTTP: Spring Framework 7.0.6, which they use, breaks the SSE transport. Java 17 or later and Spring AI 2.0 are unchanged. Every tested version is in [Compatibility](../compatibility.md).
