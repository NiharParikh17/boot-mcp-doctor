# Migrating to 0.1.1 from 0.1.0

**Migration needed: no.** Change the version to 0.1.1. No code or configuration changes are needed, but three things behave differently.

## What behaves differently

- **`get_health` answers even when health is not exposed.** In 0.1.0, `get_health` reported "Health endpoint not available" when an application hid health from HTTP. It now reads the health contributors directly. If you excluded health from Actuator's exposure to keep it away from MCP clients, that no longer works. Use `management.endpoint.health.access: none` or `boot-mcp-doctor.tools.exclude: [get_health]` instead.
- **There are new log lines.** One INFO line at startup and one for each client that connects, plus a WARN at startup when `security.allow-unauthenticated=true`.
  - To stop the connection lines, set `logging.level.com.nhparikh.repo.bootmcpdoctor.autoconfigure.ConnectionLogFilter: WARN`.
  - To keep only warnings, set `logging.level.com.nhparikh.repo.bootmcpdoctor: WARN`.
- **The message for missing health has changed.** When no health source exists, `get_health` now says `Health not available. Is spring-boot-starter-actuator on the classpath?` instead of mentioning exposure.

## Requirements

Unchanged: Java 17 or later, Spring Boot 4.1 and Spring AI 2.0. Every tested version is in [Compatibility](../compatibility.md).
